# table / struct メンバーの初期値

```dua
table Player {
    string name;
    int hp = 100;
    int[] items = [];
}
auto a = Player { name = "Ada" };
auto b = Player { name = "Bob", hp = 50 };

struct Vec2 { int x = 0; int y = 0; }
auto origin = Vec2();
auto point = Vec2(5);          // (5, 0)
auto other = Vec2({ y = 3 });  // (0, 3)
```

型メンバーは `型 名前 = 式;` と記述できます。既定値のない宣言も従来どおり使えます。
型全体への暗黙のゼロ初期化は追加しません。`Vec2 value;` や `Player value;` は引き続き使えません。

## 生成時の省略

- table は `Player { ... }` の欠落フィールドだけ補います。既定式のないフィールドは必須です。余分なフィールドの許可、重複キーの拒否、型同一性、共通metaは従来どおりです。
- struct の `Vec2(...)` は宣言順の位置引数です。省略できるのは末尾だけで、省略したフィールドすべてに既定式が必要です。
- `Vec2({ ... })` は任意の既定値付きフィールドを省略できます。既定式のないフィールドは必須です。従来のtable形式の判定と追加キーの扱いを維持します。
- メンバー宣言では既定値付きの後に必須メンバーを書けます。`struct S { int a = 1; int b; }` は `S({ b = 2 })` または `S(1, 2)` で生成します。`S()`、`S(2)` は b 不足です。
- 明示指定を優先します。計算キー・spreadで渡した値も指定済みです。明示 `null` を省略扱いにせず、その型の既存のnull制約で検査します。nullableフィールドも、既定式がなければ指定必須です。
- `T value = {...}`、`cast(T) {...}`、代入・引数・戻り値の構造型検査では既定式を実行しません。必要なら明示的に `T {...}` で生成してください。

## 評価時点・共有・スコープ

明示式を従来の順序で一度ずつ評価した後、必須フィールドの不足を確認します。省略された既定式だけを生成ごとに評価し、明示値のある既定式は実行しません。tableは型spreadの基底を列挙順に、その後に自型の宣言順で評価します。structは宣言順です。既定式も通常の型付きフィールドと同じ準備・型検査を通します。

`[]`、`{}`、AAや入れ子のリテラルは評価ごとに生成します。生成済みの値を型定義へ保存して使い回すことはありません。既定式が既存の共有変数を返す場合は、通常の型付き代入・参照共有の規則に従います。深いコピーを自動で行う仕様ではありません。structの値コピーは従来どおりです。

式は型の宣言元の字句環境とmodule contextで評価します。外側の変数の現在値を読み、生成呼出し元の同名ローカル変数には置き換わりません。生成途中のメンバー名や新しい個体の `this` は自動束縛しません。`int x = y;` の y は、宣言元の外側にある変数です。他メンバーを暗黙に参照するものではありません。外側に既に字句束縛された `this` があれば、通常の外側変数として扱います。

型spreadは既定式を元の宣言元環境ごと継承します。同名フィールドの衝突は、同じ型・同じ既定値でも従来どおりエラーです。

通常の型宣言は追加の `new Module` で再実行されません。このため、型の既定式は宣言元実体の環境を保持します。別実体で生成しても、その実体の `instance` 変数や `self` / `scenes` へ自動切替しません。生成元moduleの初期化失敗やcontext終了後に、その環境に属する既定式を実行することはできません。

例外には既定式の定義元ソースと位置を保持します。式評価には通常の実行量・呼出し深度制限を適用します。既に実行した明示式・既定式の副作用は、後続の型不一致や例外でも巻き戻しません。

## 診断・補完・保存

型検査を有効にすると、使われない既定式でも静的に分かる型不一致を診断します。解析のために式を実行しません。動的な値の型や計算キー・spreadの実内容は実行時にも検査します。

共有解析API v1の型記述に `defaultFields`（自型の既定値付きフィールド名）と `fieldOrder`（自型の宣言順）を追加します。既存の `fields` と `baseTypes` を維持します。継承分は基底の記述をたどります。既定式そのものや評価値は解析APIへ出力しません。拡張はnamed tableの補完に「既定値あり・省略可」を表示し、structの位置引数では省略可能な末尾を署名へ反映します。

この構文には対応する処理系とチェッカーが必要です。Scene／素材の保存形式は変更しません。JSONや `toScriptLiteral` は生成後のデータを保存し、既定式・型宣言・型同一性を永続化するものではありません。

回帰検証は `tests/member_defaults.d`、拡張の `test/memberDefaults.test.js` にあります。
