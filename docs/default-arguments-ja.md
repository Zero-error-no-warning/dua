# Duaのデフォルト引数

```dua
int sum(int a, int b = 2, int c = 3){ return a + b + c; }
sum(1);       // 6
sum(1, 5);    // 9
sum(1, 5, 6); // 12

auto scale = (int value, int factor = 2) => value * factor;
```

末尾に連続する任意個数の固定引数に `= 式` を書けます。必須引数は既定値付き引数より前です。既存の型付きラムダ（ブロック/`=>`/`:>`）も対応します。型名を省略する新しいラムダ構文は追加しません。名前付き引数、途中だけの省略、可変長引数自身の既定値はありません。可変長末尾の前の固定引数には既定値を付けられます。

## 評価規則

- 呼出し元の明示引数を従来どおり評価した後、省略分だけを左から評価します。既定式は定義時に実行しません。
- 関数の定義元のクロージャ/モジュール文脈と、新しい呼出しフレームを使います。定義元の変数・`self`/`scenes`、既に束縛された前の引数を参照できます。呼出し元の同名ローカル変数に置き換わりません。
- 自身または後続の未束縛引数をその場で読むとエラーです。外側の同名変数へフォールバックしません。既定式で作ったクロージャが、全引数束縛後に後続引数を読むことは通常の捕捉として扱います。
- `null` を渡すことは省略ではなく、その型の通常のnull制約で検査します。配列のnull判定と空配列の内容比較は区別し、必要なら `is null` を使います。
- 配列/tableリテラルは式評価ごとに生成されます。既存の共有変数を既定式で参照すれば、通常の参照共有を保ちます。structのコピー規則も既存どおりです。
- 既定値も明示引数と同じ実行時型検査を通ります。型検査を有効にした場合は、使用しない既定式でも静的に分かる型不一致を診断します。解析のために既定式を実行しません。

```dua
int next(int a, int b = a + 1){ return b; }
// next(3) は4。自身/後続を先に読む int f(int a=b,int b=1) は呼出し時エラー。
```

importした公開関数、UFCS、Dへ渡すcallback、coroutineにも同じ規則を適用します。coroutineのresumeごとに既定式を再評価せず、一度の関数呼出しの引数として保持します。既定値なしの関数とD側からbindしたAPIの既存既定値は変更しません。

新構文は対応するDua処理系が必要です。古いゲーム実行EXEや古いチェッカーでは解析できません。シーン/素材の保存形式は変更しません。
